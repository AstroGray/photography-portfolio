Organize a project
Before anything else
Every shoot becomes a folder under ~/Photos/. Same name in the same shape, every time. Future-you scanning a folder list should be able to tell what each one is in 2 seconds.
1

Pick a folder name

Format: YYYY-MM-DD_category_descriptor — all lowercase, hyphens within tokens, underscores between tokens. Date first so chronological sort = visual sort.

2026-05-03_personal_susu-prom
Just two categories client (paid work) · personal (everything else). The subject lives in the descriptor — niles-headshot, morozko-forge, puerto-vallarta. Binary is easier than clever.
Rules No spaces · no capitals · no apostrophes · don't repeat the year in the descriptor · drop articles like "the" / "a"
2

Create the standard subfolders

Same four folders inside every project. Empty is fine — they fill up as the project moves along.

mkdir -p ~/Photos/2026-05-03_personal_susu-prom/{raws,selects,edits,delivered}
Resulting structure: 2026-05-03_personal_susu-prom/ ├── raws/ source files from the camera ├── selects/ narrowed selection for editing ├── edits/ exported finals (jpegs, prints) └── delivered/ what the client actually got
3

Drop in raws and proceed

Card → raws/ first. Once raws are in place, you can run a backup immediately (see next section), then continue with culling and editing over the following days. Each phase gets its own backup checkpoint.

Back up a project
B2 cloud + external drive · 3-2-1
One command sends a project folder to both the Backblaze B2 archive and the external drive. Re-running is cheap — only new files transfer. Run after each phase: raws → selects → edits → delivered.
1

Plug in the external drive (if you have one)

Drive should mount at /Volumes/PhotoBackup. If not plugged in, the script will warn and continue with just the B2 archive — you can re-run later to catch the drive up.

ls /Volumes/
Should list PhotoBackup among the mounted volumes if the drive is connected.
2

Go to the ops repo

cd /Users/graysonhammon/photography-ops
3

Dry run first (always, for big uploads)

Optional but smart for first-time uploads or after large editing sessions. Same command as the real run, just with --dry-run appended.

./scripts/backup-project.sh ~/Photos/2026-05-03_personal_susu-prom --dry-run
Lists files that would transfer to B2 and (if drive is mounted) to the external drive. Nothing actually moves. Verify the file count looks right.
4

Run the backup

Same command, no --dry-run. Pushes to B2 archive AND copies to external drive in one shot.

./scripts/backup-project.sh ~/Photos/2026-05-03_personal_susu-prom
Two progress sections (B2, then drive), then a verification block comparing sizes. If the drive is missing you'll see a warning and a "partial" status — that's fine, re-run later when plugged in.
Re-runs are safe and fast Both rclone and rsync skip files that already exist unchanged. Running the same command after every project phase only transfers what's new.
5

Verify on B2 (occasional sanity check)

Confirm files actually landed. Lock should show as Governance Mode in the B2 web UI.

./scripts/archive-list.sh 2026-05-03_personal_susu-prom
Every file with size. Or browse to the bucket in B2 web UI; check one file's Object Lock: Governance Mode, expires ~1 year out.
6

Occasional: check total archive size / cost

./scripts/archive-list.sh --size
Total bytes used. Multiply GB × $0.006 for the monthly cost.

If something breaks

"AccessDenied: not entitled"
The B2 application key is wrong, expired, or deleted. Rotate via B2 web UI → Application Keys → create new → update rclone with rclone config → e → s3 → replace access_key_id and secret_access_key.
"CreateBucket: AccessDenied"
rclone is trying to recreate the bucket. Check that no_check_bucket = true is set: rclone config show s3
"⚠ External drive not mounted"
Drive isn't plugged in, or it's named something other than PhotoBackup. B2 was still updated. Plug in the drive and re-run. If your drive has a different name, edit EXT_VOLUME at the top of backup-project.sh.
Wanted to delete a file, B2 refuses
Object Lock is doing its job. File is locked for 1 year from upload. For real cleanup, create a temporary B2 key with bypassGovernance capability, then use rclone delete --s3-bypass-governance-retention. Delete the temp key afterward.
Need to restore from the archive
./scripts/archive-restore.sh 2026-05-03_personal_susu-prom ~/restored/susu-prom
Update the portfolio
Cloudflare R2 · Public · grayhammonphoto.com
Add or remove photos on the live site. The People / Places / Things folders are the source of truth — process-photos.sh mirrors them to R2 (adds new, removes any you've taken out), then rebuild index.html. Site rebuilds on push.
1

Sort selected JPGs into tab folders

Hand-pick the ones you want public, then drop each into the folder for its tab: Photos/People/ (portraits), Photos/Places/ (landscapes / location shots), or Photos/Things/ (everything else). The folder is what puts a photo in that tab. Originals go into the B2 archive separately (other workflow).

cd /Users/graysonhammon/photography-portfolio-site
Working from the repo root. Each new JPG (any case) sits in Photos/People, Photos/Places, or Photos/Things. Files left loose in Photos/ are skipped with a warning.
Don't confuse the two "categories" These People/Places/Things folders live in the repo's ./Photos/ and only control gallery tabs. They're unrelated to the client/personal categories in your ~/Photos shoot library.
2

Sync folders to R2, write categories

Generates 800/1600/2400px variants (flat names, so URLs never change) and mirrors your folders to R2 — uploading new photos, deleting any no longer in a folder, and pruning the local cache to match — then rewrites docs/photo-categories.tsv. Cached photos are skipped. Empty folders? It refuses to run rather than wipe the site.

./scripts/process-photos.sh
Lists any photos being removed, an rclone sync progress bar, then "N photos live — X new variants generated, Y cache files pruned, Z removed from R2."
3

Regenerate gallery HTML

Reads the photo list from R2 and the tabs from docs/photo-categories.tsv, then rewrites the gallery in index.html — each photo tagged with its category.

./scripts/generate-gallery.sh
"Found N photos" → "Updated ./index.html with N photos." Any photo not in the manifest is listed as defaulting to "things."
4

Preview locally (optional but smart)

Open index.html in a browser and click through People / Places / Things to check each tab looks right before pushing. (Page lands on People.)

open index.html
5

Sanity-check the diff

git diff index.html | head -40
Should show new <div class="gallery-item" data-category="…"> blocks being added, with srcset attributes ending in 2400w".
6

Commit and push

Pushing to GitHub triggers a Cloudflare Pages build, which then hosts the site. Changes go live in ~1–3 minutes.

git add -A git commit -m "Update gallery" git push
7

Verify the live site

Wait ~2 minutes, then open in a private/incognito window (skips cache).

open -na "Google Chrome" --args --incognito "https://grayhammonphoto.com"

If something breaks

"didn't find section in config file (r2)"
The r2 rclone remote got renamed or deleted. Check with rclone listremotes. If it's named something else, either rename it back to r2 or edit the BUCKET_PATH/R2_REMOTE variables in the scripts.
process-photos.sh: "magick: command not found"
Install ImageMagick: brew install imagemagick
generate-gallery.sh: "no photos found"
R2 bucket is empty or path is wrong. Verify: rclone ls r2:grayhammon-photos/photos | head
A photo didn't show up / got skipped
It's probably sitting loose in Photos/ instead of inside People/, Places/, or Things/. Move it into a category folder and re-run process-photos.sh then generate-gallery.sh.
A photo is in the wrong tab
The tab comes from the folder. Move the original between Photos/People, Photos/Places, Photos/Things, then re-run process-photos.sh and generate-gallery.sh. R2 stays flat, so the URL doesn't change, and the manifest is rebuilt from the folders — no hand-editing needed.
Site shows old photos after push
Browser cache. Try incognito. If it's still cached: Cloudflare dashboard → Caching → Configuration → Purge Everything.
Want to remove a photo from the site
Delete it from its folder and re-run — the folders are the source of truth, so process-photos.sh syncs the deletion to R2, prunes the cache, and drops it from the manifest. It lists what it's removing first. Your B2 master is untouched.
rm Photos/People/DSC01234.jpg ./scripts/process-photos.sh ./scripts/generate-gallery.sh git add -A && git commit -m "Remove photo" && git push
Heads up The folders now drive deletions. Anything missing from Photos/ (a moved file, an unmounted drive) gets removed from the site on the next run — that's why process-photos.sh refuses to run on empty folders.
